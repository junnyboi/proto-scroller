# Narrative UI and Localization Implementation Audit

**Audit domain:** Narrative UI and localization
**Approved contract:** `docs/PROJECT_CHOIR_STORY_PROPOSAL.md`
**Inspected revision:** `9f6e1279f2a77822e066f2337a21dc1e8b59cb17` (`main`, clean before this report)
**Production files were not edited.**

## Architectural finding

The game already has strong, deterministic presentation primitives, but it does **not** yet have campaign, dossier, codex, transmission, or ending-choice UI. The safest implementation is to keep `NarrativeDirector` and campaign persistence outside the UI, pass immutable presentation snapshots/events into small `Control`/`CanvasLayer` views, and preserve the current separation in which `CityRunLifecycle` translates domain signals into `GameplayHUD` calls. Transmissions must be nonmodal observers; the dossier codex and ending choice must be explicit focus-owning modals; campaign progress must be read-only UI derived from a separate versioned campaign save.

Do not turn `GameplayHUD` into a narrative state owner, do not make UI nodes read/write the campaign save, and do not overload directive completion or `RunSummarySnapshot` as dossier persistence.

## Recommended implementation shape

### Presentation-only classes

Create the following UI classes. They should accept IDs, localization keys, and immutable snapshots—not references to `NarrativeDirector` or mutable save dictionaries.

| Proposed class / file | Contract |
|---|---|
| `TransmissionOverlay` — `game/scripts/ui/transmission_overlay.gd` | `signal transmission_finished(event_id: StringName)`; `present(event: TransmissionPresentation)`; `dismiss(event_id)`; `advance_for_test(delta)`; queue by deterministic sequence number. Full-rect `Control`, `mouse_filter = IGNORE`, no pause/focus ownership. A 2–5 s card can expire while play continues. |
| `DossierToast` — `game/scripts/ui/dossier_toast.gd` | `present(dossier_id, title_key)` and deterministic timeout; nonmodal, noninteractive, coalesces repeated IDs. |
| `DossierCodexOverlay` — `game/scripts/ui/dossier_codex_overlay.gd` | `signal closed`; `open(snapshot: CampaignProgressSnapshot, return_focus: Control)`; `close()`; localized filter/tabs/detail; locked entries reveal no protected body. It owns focus only while visible and supports keyboard, gamepad, mouse, and touch. |
| `NarrativeSummaryPanel` — `game/scripts/ui/narrative_summary_panel.gd` | `present(snapshot: CampaignProgressSnapshot, run_delta: NarrativeRunSummary)`; `clear()`; read-only and embedded in the terminal overlay. |
| `EndingChoiceOverlay` — `game/scripts/ui/ending_choice_overlay.gd` | `signal ending_selected(choice_id: StringName)`; `show_choices(options: Array[EndingChoicePresentation])`; one-shot selection guard; no persistence writes. Display locked Disentangle requirements, but only focus selectable choices. Pause lease remains owned by lifecycle/runtime orchestration. |
| `CampaignProgressPanel` — `game/scripts/ui/campaign_progress_panel.gd` | Compact title-briefing readout for recovered dossiers, five evidence nodes, and last ending; opens codex but never mutates campaign state. |

If the narrative/campaign domain supplies different snapshot class names, retain the same boundary: **UI receives value-like, read-only presentation data and emits user intent only**.

### Wiring and signal flow

1. `CitySlice` constructs `GameplayHUD` as today and supplies narrative presentation children during HUD setup. A `NarrativeDirector` (owned elsewhere) observes `CityWorldStream.district_changed`, streamed destruction signals such as `StreamedDestructibleRuntime.building_cell_destroyed`, encounter/boss signals, and run completion.
2. `CityRunLifecycle` remains the presentation adapter. Connect narrative signals such as `transmission_requested`, `dossier_recovered`, `campaign_progress_changed`, and `ending_choice_requested` there (or in a sibling `NarrativePresentationCoordinator`), then call HUD methods. Do not connect combat nodes directly to UI nodes.
3. Extend `DistrictTransitionBanner.present()` compatibly, for example `present(district, logical_chunk, immediate_target_key := "")`; derive keys such as `district.business.name` instead of rendering `CityDistrictProfile.display_name` directly. Existing callers and tests remain valid.
4. Add `GameplayHUD.present_transmission()`, `present_dossier()`, `set_campaign_progress()`, and `show_ending_choices()` as thin forwarding methods. In `_apply_responsive_layout()`, call each child’s layout method alongside the existing directive/upgrade/tutorial children.
5. For a codex available from title briefing, inject the latest campaign snapshot from `Main._show_title()` into `TitleScreen`. `TitleScreen` emits intent or owns only the overlay view; campaign loading/saving remains outside the scene. Add live localized labels rather than encoding new narrative copy in briefing art.
6. At finale, orchestration acquires `RunPauseCoordinator.acquire(&"ending_choice")`, presents `EndingChoiceOverlay`, commits the emitted ID through campaign/narrative logic, then releases the exact token. Never reuse `_terminal_pause_token` implicitly and never infer an ending from button text.
7. Before `GameplayHUD.show_district_complete()`/`show_game_over()`, pass the frozen campaign/run narrative snapshot into `NarrativeSummaryPanel`. Persistence commits must occur before snapshot creation so summary and subsequent title codex agree.

### Localization key taxonomy

Use stable semantic IDs, not English sentences, and keep placeholders identical between catalogs:

```text
narrative.title.hook
narrative.district.business.name
narrative.district.business.arrival
narrative.district.business.target
narrative.transmission.echo7.business.01.speaker
narrative.transmission.echo7.business.01.body
narrative.dossier.business.01.title
narrative.dossier.business.01.summary
narrative.codex.heading
narrative.codex.progress
narrative.summary.recovered
narrative.ending.purge.name
narrative.ending.purge.description
narrative.ending.disentangle.name
narrative.ending.disentangle.requirement
narrative.ending.ascension_failure.title
```

Keep speaker names, dossier IDs, district IDs, and numerals as placeholders only when the two languages intentionally share the token. After locale selection, call `L10n.apply_locale_font(root)` for every newly constructed narrative root. Do not rely on English fallback for release content.

## Compatibility risks

1. **Baked briefing localization can drift.** `%BriefingArt` currently selects separate English/Chinese images while `title.story` is dead catalog copy. Adding more text to images would bypass catalog parity, font, accessibility, and wrapping tests. Render new narrative copy as labels.
2. **Locale changes are not broadcast.** `L10n` caches catalogs and locale globally but has no signal; only `TitleScreen.select_language()` manually refreshes. Any codex already open during a locale switch will be stale unless explicitly refreshed.
3. **District names are raw English data.** `CityDistrictCatalog` stores values such as `The Ledger Spine`; current banner also hard-codes `FORWARD SECTOR`. Treat them as compatibility data until localized keys are added; do not mass-convert profile fields without auditing tests and art manifests.
4. **Fixed geometry can collide.** HUD, directive, upgrade, tutorial, terminal, and district banner layouts all use explicit coordinates. Every narrative surface must be asserted at both design sizes, especially long Simplified Chinese transmission and ending requirement text.
5. **Focus can leak into hidden controls.** Existing terminal/directive overlays focus on open but generally do not restore previous gameplay focus. Codex must store/validate the previous focus owner; ending buttons must clear focus before hiding and must not leave locked choices focusable.
6. **Pause semantics are leased and partial.** `RunPauseCoordinator` is not `SceneTree.paused`; bypassing it can leave projectiles, hazards, mobile input, or attacks active. Conversely, acquiring it for ordinary transmissions violates the contract that radio fragments do not interrupt combat.
7. **Overlay arbitration is currently implicit.** Directive choices, upgrades, terminal choice, codex, and ending choice can compete for z-order/focus. Add one modal-presentation policy/coordinator; queue transmissions behind modal copy or continue them visually without stealing focus.
8. **Terminal signals are not ending semantics.** `extract_requested`/`continue_requested` and the cycle summary are run-flow controls. Reusing them for Purge/Disentangle would make analytics, tests, and save commits ambiguous; use `ending_selected(choice_id)`.
9. **Summary consistency depends on commit order.** `RunSummarySnapshot` freezes once. If dossier persistence is committed after UI snapshot creation, the post-run summary and next title codex will disagree.
10. **Fallback masks catalog omissions.** `L10n.t()` returns English or the key string; runtime success is not proof of complete Chinese localization. Release gating must retain strict catalog parity, placeholder, neutral-token, and glyph checks.

## Acceptance boundary

The UI slice is safe to merge when transmissions never pause or capture input, codex/ending modals have deterministic focus and lease behavior, every visible narrative string exists with placeholder and glyph parity in English and Simplified Chinese, all narrative surfaces pass both canonical responsive sizes, and campaign progress is rendered from—but never owned or persisted by—the UI.
